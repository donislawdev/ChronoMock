Exit codes

What the code at the end of each chrono command means, for a script that has to decide what happens next.

chrono run

The code is the session's verdict, not the code the application ended with. An application that ran happily on the real date has not tested the date at all, and a script that read only the application's own code would never notice. That code is still there: in the report, on the line exited, and in --json.

{{exit_codes_run}}
  • 0, 10, 11 and 4 are the verdict: whether the date reached the application.
  • 8 also comes after a verdict, which is then on the screen but not in the file.
  • 12 means the application left before it could be judged.
  • The rest mean the run did not get that far, so they say nothing about the application.

In a pipeline, a step that only passes on a full verdict looks like this. The CLI and CI page has the reasoning and the caveats about runners. 

chrono run .\build\app.exe --at 2038-01-19T03:14:00 --ticks 20 --timeout 120 --report evidence.txt
if ($LASTEXITCODE -ne 0) { throw "chrono run ended with $LASTEXITCODE" }
