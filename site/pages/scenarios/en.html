Scenarios

Ready-made dates to test with: the last day of a month, the leap day, the last second of a trial. The window calls them scenarios and the command line calls them presets.

Using a scenario

A scenario is a date and time worked out for you, with one line on what it tests. Picking one fills in the date and nothing more: it never starts a session on its own.

  • Run an app lists, under Scenarios, the ones that need no value from you. Picking one fills in Starts at.
  • Calculator lists, under Scenarios, the ones it can work out, with a field for each value a scenario asks for. Use this date takes the result over to Run an app.
  • On the command line, --preset takes the name to type, and each value is one --param.
chrono run "C:\apps\test.exe" --preset month-end
chrono calc --preset trial-last-day --param start_date=2027-01-01 --param trial_length=45d

Some scenarios only make sense for an application that is running: a clock 90 seconds ahead means something to an application, not to a calculator. Others only make sense in the calculator, such as the day someone turns 18. Each one below says where it works.

Giving a value

A scenario that counts from a date only you know asks for it: a date of birth, the day a trial started. In the Calculator each value has its own field. On the command line it is --param, the value's name, an equals sign and the value.

  • A date is written year first: 2027-01-01.
  • A length is a number and a unit with no space between them: 45d. The units are those of --shift, and bd counts business days. A number on its own is refused, because it does not say what it counts.
  • A choice is one of the words the scenario lists, such as on_day.

A value the scenario has a default for, such as a trial of 30 days, can be left out. A value with nothing to fall back on stops the command with a message that names it. Business days are counted in a holiday calendar: a scenario made for one market counts in that market's calendar, and chrono calc --calendar picks another.

Writing your own

A scenario is a small text file in JSON. This one checks the first day an invoice is overdue:

{{preset_example}}
  1. Save it as invoice-overdue.json. The file name without .json must be the same as id.
  2. Put it in the folder the program reads. chrono presets names that folder on its second line. In the window's zip package it is the presets folder beside ChronoMock.exe. A folder under Program Files takes administrator rights to change.
  3. Run chrono presets again. Your scenario is in the list, or among the files left out, with the reason.
chrono calc --preset invoice-overdue --param issued=2027-03-01
Chrono Mock - date calculator
  preset:   invoice-overdue - First day an invoice is overdue
  explains: Does the app mark an invoice overdue on the day after its due date, and not on the due date itself?
  base:    2027-03-01T00:00:00
  step 1:  shift +14 days  -> 2027-03-15T00:00:00
  step 2:  shift +1 days  -> 2027-03-16T00:00:00
  step 3:  set time 08:00:00  -> 2027-03-16T08:00:00
  result:  2027-03-16T08:00:00
  ...

What the file holds

KeyWhat it is
schemaAlways chronomock.preset/1.
idThe name to type, the same as the file name: letters, digits, - and _.
name, explainsThe name and the one line on what it tests, for each language. en is required, and the window shows its own language when the file has it.
applies_tosubstitution for an application that runs, calculator for the Calculator, both for both.
marketnull, or us or pl to count business days in that market's calendar.
parametersThe values it asks for. Each has an id, a type (date, duration for a length, or variant for the day before, on or after: day_before, on_day, day_after), a label for each language and, if you want one, a default.
momentWhere the date starts, base, and the steps taken from there, in order.
time_modeThe speed chrono run starts at. multiplier 1 is real speed.

Where the date starts

baseWhat it is
"today"Midnight today, in the session's time zone.
"now"This moment, to the second.
{ "absolute": "2027-03-01T09:00:00" }That time on the clock of the session's time zone: 9 in the morning wherever the test runs.
{ "absolute_utc": "2038-01-19T03:14:07Z" }That moment in UTC, the same instant in every zone. For dates whose point is the instant, such as the 2038 limit.
{ "parameter": "issued" }A date the person using it gives.

Steps

Each step is the same as an option of chrono calc and takes the same values, so the calc options say what each one does.

StepSame as
{ "shift": { "sign": "+", "amount": 1, "unit": "days" } }--shift +1d. The unit is a code or its full name.
{ "shift": { "sign": "+", "parameter": "term" } }--shift by a length the person gives.
{ "shift": { "parameter": "boundary" } }A day back, none or a day forward, by the choice the person makes. No sign: the choice has one.
{ "set_time": "08:00:00" }--set-time
{ "snap": "eom" }--snap
{ "nearest": "nbd" }--nearest
{ "zone": "+05:45" }--to-zone: the steps after it count in that zone.

A scenario says when a date is, never which program to run, so there is no place in the file for a path. A file from someone else can set the date and the speed your test starts with, and it cannot start a program.
