タイムトラベルテスト（time travel testing）

タイムトラベルテストとは、ソフトウェアを今日以外の日付で動かすことです。来月、年の最後の 1 秒、2 月 29 日、2038 年。その日が来たときに何が起きるかを確かめます。見つかるのは日付を待っているバグです。間違った月を締める帳票、いつまでも切れないライセンス、1 日長く受け付けられるトークン。

なぜ手法が必要なのか

日付に左右される動作はたくさんあります。試用期間とライセンスの期限切れ、サブスクリプションの更新、証明書やトークンの有効期間、キャッシュの期限切れ、月末と年末の締め処理、利息、リマインダー。どれも待って試すことはできず、どれも同じもの、つまり現在時刻をどこかから読んでいます。タイムトラベルテストとは、その「どこか」を制御することです。

time machine testing と呼ばれることもあります。呼び名が何であれ、時間を動かせる場所は 4 つあり、それぞれが世界の違う部分を動かします。

時間を動かす 4 つの方法

時間が動く場所新しい日付が見えるもの向いている用途代償
マシンのシステム時計そのマシン上のすべてOS そのもの、タスク スケジューラ、サービスのテスト。使い捨ての仮想マシンなら何でもドメイン ログオン、証明書、時刻同期が壊れ、変更には管理者権限が必要
コードの中の時計その時計に問い合わせるコード変更できるコードの単体テスト。注入した時計や、テスト フレームワークの偽タイマーソースコードと、時計を渡す設計が必要。プログラムとしてしか手元にないアプリには役立たない

時間が動いたら何をテストするか

  • 境界 - 月、四半期、会計年度の最終日と、アプリの実行中に年が変わる瞬間。
  • 暦 - 2 月 29 日、1970 年より前の日付、2038 年の 32 ビットの限界。
  • 自社のライセンス - 試用期間の最終日、その翌日、ずっと前に切れたライセンス。
  • 経過時間 - カウントダウン、セッションのタイムアウトなど 2 つの時点の間で測るもの。時間が実際より速く進んで初めてバグが見えます。
  • タイムゾーン - 5 つ離れたタイムゾーンにいて、あなたより先に一日が終わる顧客。

Windows アプリのタイムトラベルテスト

Chrono Mock はアプリを専用の時計で起動し、システム時計には触れません。マシンのほかの部分は本物の日付のままです。時計はどの時点からでも始められ、止めることも、速く進めることも、アプリを開いたまま飛ばすこともできます。 

# アプリには 2027 年の最後の 10 秒が見え、自分で 2028 年に入る
chrono run "C:\apps\test.exe" --at 2027-12-31T23:59:50

# 1 分で 1 日: 30 日の期間が 30 分で終わる
chrono run "C:\apps\test.exe" --mode x1440

# 日付の代わりに名前付きシナリオを使い、証拠をファイルに書き出す
chrono run "C:\apps\test.exe" --preset month-end --report session.txt

# 今日の日付で始め、数秒後にアプリを開いたまま 2038 年へ飛ぶ
chrono run "C:\apps\test.exe" --jump-after 5:2038-01-19T03:14:05 --zone +00:00

ウィンドウでも同じです。アプリを選び、シナリオを選ぶか日付を入力し、速度を選んで Start を押します。

タイムトラベルが起きたと知るには

どの手法にも同じ弱点があります。アプリは、その手法が動かしていない経路で時刻を読むかもしれません。アプリが新しい日付を一度も見ていないせいで通るテストは、テストがないより悪いものです。Chrono Mock のセッションは毎回、判定、アプリが実際に読んだ時刻チャネルとそれぞれの回数、読み逃したチャネルで終わります。 監査のしくみ →

対象外のもの

  • スマートフォンとほかの OS。 Chrono Mock が動かすのは Windows アプリです。Android や iOS のアプリ、Linux や macOS のプログラムのタイムトラベルテストには、そのプラットフォーム向けのツールが必要です。
  • サーバー側。 アプリがサーバーから受け取る日付は、サーバーの日付のままです。アプリがネットワーク接続を開くのを見ると、セッションはそれを伝えるので、確認が必要だとわかります。
