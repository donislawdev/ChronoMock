Run an app

The tab that starts an application on another date. Every field and option from top to bottom, with the command line option that does the same.

Application

Choose… picks the .exe to run. The list beside it holds the applications you have run before, so a second test of the same one is a pick from the list. On the command line the application is the first value after chrono run.

Date and time

FieldWhat it does
Starts atThe date and the time the application starts at. Type the date as YYYY-MM-DD or pick it from the calendar. The time is 24-hour, and empty means midnight. Same as --at.
Today, NowFill in today at midnight, or this moment, in the session's time zone.
Time zoneThe zone the application finds itself in, and the one the date and time are read in. A fixed offset from UTC, with no change for daylight saving. Same as --zone.
From nowA sign, a number and a unit, such as + 90 days. Fill the date puts that moment into Starts at.

Scenarios

Ready-made dates, each with one line on what it tests, and a box to search them. Picking one fills in Starts at and never starts the session. This list has the scenarios that need no value from you. The ones that ask for a value, such as a date of birth, are worked out in the calculator, and Use this date there brings the result back here. Scenarios lists them all.

Speed and options

Folded, the section shows a short tag for each option you changed, so a change does not stay out of sight.

OptionWhat you get
SpeedHow fast the fake clock runs. ×1 is real speed, Frozen stops it, and ×10, ×60 and ×1440 run it that many times faster: at ×1440 a day passes in a minute. Same as --mode.
Also speed up timers and countdowns inside the application Timers, waits and countdowns follow the speed too, not only the date and time on the clock: a reminder set for an hour comes after a minute at ×60. Same as --scale-duration.
Also speed up timers that measure elapsed time The clocks an application measures how long something took with follow the speed too. It can make animation and video inside the application look wrong. Same as --scale-qpc.
Start even if the fake clock turns out not to work When the check right after the start finds that the application does not read the fake clock, it is normally ended, because what it shows would come from the real clock. With this ticked it goes on, and the session is marked unreliable everywhere it appears. Same as --force.
Reach the web pages inside the application On from the start. Pages an application shows through a built-in web engine follow the fake clock too. For the session the engine opens a local debugging port, which other programs on this computer can reach while the application runs. Unticked, it is --no-embedded.
Reach the web pages of an application that runs as administratorThe same for an application that runs as administrator, which needs one setting written to the machine's registry for the session and removed afterwards. While the application runs, any program on this computer can reach its pages. Only when Chrono Mock itself runs as administrator. Same as --elevated-embedded.
Keep timers at speed in hidden windows For Chromium and Electron applications and for pages inside an application, which slow the timers of a minimized window down. The application keeps working at full pace while its window is minimized. Same as --keep-background-timers.
Switch off the Gecko sandbox{{next_release}} For applications on Mozilla's Gecko engine: their web pages follow the fake clock too. The application runs without the Gecko sandbox until it closes, so open only pages you trust in it. Same as --no-gecko-sandbox.
ArgumentsWhat the application is started with, as you would type it in a terminal: an argument with spaces goes in quotes. Same as --args.
Working folderThe folder the application starts in. Empty starts it where it normally would. Same as --cwd.

The footer says in words what the application will see and at what speed, and Start starts it.

During the session

  • Fake clock is what the application reads, Real clock what the rest of the computer reads. Under each is the time that has passed on it.
  • Speed switches between ×1, ×10, ×60, ×1440 and Freeze. The box beside them takes any speed, such as 500, and Set applies it.
  • Jump moves the fake clock an hour or a day either way, and Jump to to a date and time read in the session's zone. Time an application measures as elapsed never runs backwards, also after a jump back.
  • Next to Running is the verdict so far.
  • Stop session puts the application back on the real clock. It does not close the application, and the result says if it is still running.

The result

The session ends when the application closes, or when you stop it. The verdict comes first, with one line on what it means, then how the session ended.

VerdictWhat it means
WorksEvery process that read the time saw the fake clock.
PartialThe application read some of its time from the real clock, so the test may be unreliable.
FailsIt went on reading the real clock where it matters, so the session was refused as unreliable.
UndeterminedWhat it read could not be determined. That never counts as working.
  • What the application saw: the moment it started at, the speed, where the fake clock got to, and how much time passed on each clock. When the computer slept during the session, it says so.
  • What the application read: each Windows function that reads the time and that the application used, the clock it answered with and how many times it was called. fake clock and real clock say which one answered. real clock, by design is one left on the real clock on purpose. not watched is one Chrono Mock could not watch, so it cannot say. late means the function was put on the fake clock only after the application had started. The time source audit explains it in full.
  • Copy summary copies a report to paste into a ticket.
  • Previous sessions lists the sessions before. Set up again fills the tab with one of them without starting it, Forget this session removes one, and Clear the history removes them all.
  • New session goes back to the setup and keeps everything you entered.
