Command line reference

Every command of chrono.exe and every option it takes. The exit codes have a page of their own.

Before you start

  • Two copies of chrono.exe. The command line download has chrono.exe for 64-bit applications and x86\chrono.exe for 32-bit ones. The window picks the right one by itself, the command line does not. With the other one the session does not start: the report says different bitness and the command ends with code 1, so run it again with the other chrono.exe.
  • Dates and times are written YYYY-MM-DDTHH:MM:SS, such as 2026-03-31T23:59:00, in the session's time zone unless the option says UTC.
  • A step is a sign, a number and a unit: +1d, -2h, +3mo. m is minutes and mo is months.
  • Help is in the program too: chrono --help for every command, chrono run --help for one.
  • The report at the end of chrono run is explained line by line on Reading the report.
  • For a program to read, --json writes the answer of any command as JSON. JSON output names every field.

chrono run

Starts the application, moves its clock and waits until it closes. Then it prints a report that says whether the date reached the application, and ends with an exit code that says the same to a script. 

# Start at a moment, with the clock running sixty times faster
chrono run .\build\app.exe --at 2038-01-19T03:14:00 --mode x60

# The last day of this month, for thirty seconds, with the report saved as evidence
chrono run .\build\app.exe --preset month-end --ticks 30 --report evidence.txt

# See what a session would be without starting anything
chrono run .\build\app.exe --at +1y --dry-run
{{cli_options_run}}

chrono calc

Each option is one step, and the steps run in the order you write them. The result after every step is printed, so a step that did something unexpected shows where it happened: 

chrono calc --base 2026-01-31T09:30:00 --shift +1mo --snap eom --zone +01:00
Chrono Mock - date calculator
  base:    2026-01-31T09:30:00
  step 1:  shift +1 months  -> 2026-02-28T09:30:00
           ^ day clamped from 31 to 28 - that month is shorter
  step 2:  snap to end of month  -> 2026-02-28T23:59:59
  result:  2026-02-28T23:59:59
  ...

After the result come the same moment in a dozen formats, the day of the week, the week number and, with --calendar, whether it is a business day.

chrono presets

Shows which presets --preset can use right now, so a typing mistake in a preset file shows up here, with its reason, rather than in the middle of a test run.

{{cli_options_presets}}

chrono calendars

The same for the holiday calendars of --calendar.

{{cli_options_calendars}}

chrono version and chrono license

chrono version prints one line a script can read, such as chrono {{version}} (x64, protocol 1). chrono license prints the licence, GPL-3.0, and what is bundled with the program.
