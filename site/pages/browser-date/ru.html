Изменение даты в Chrome или Firefox для тестов

Обычные ответы - расширение, которое подменяет дату на странице, или часы тестового фреймворка. Chrono Mock запускает сам браузер с его собственными часами - каждая вкладка и каждый worker, любая дата, остановленная или ускоренная, - и не трогает часы Windows и все остальные программы.

Chrome

Chrome запускается с чистым одноразовым профилем и локальным портом отладки, и каждая страница и каждый worker берёт время JavaScript из сессии: Date.now, new Date(), performance.now, setTimeout, setInterval и часовой пояс сессии. Сам браузер живёт по настоящей дате, поэтому сайты по HTTPS продолжают открываться - проверено на сессии, установленной на 2040 год. 

# Chrome в последние десять секунд 2027 года, в шестьдесят раз быстрее
chrono run "C:\Program Files\Google\Chrome\Application\chrome.exe" --at 2027-12-31T23:59:50 --mode x60 --args "http://localhost:8080/"

Профиль не ваш: ни сохранённых входов, ни расширений, и он удаляется по окончании сессии. Другие браузеры на основе Chromium работают так же. Как работает режим Chromium →

Firefox

Firefox запускает страницы в процессах в песочнице, куда сессия не может войти, поэтому ему нужен --no-gecko-sandbox. Тогда страницы стартуют вне песочницы, присоединяются к сессии и следуют её часам, скорости, скачкам и часовому поясу. Firefox работает без этой защиты, пока его не закроют, поэтому открывайте в нём только страницы, которым доверяете. Дайте ему собственный профиль через -no-remote -profile и пустую папку, чтобы он не передал страницу уже открытому Firefox. 

# Firefox в последние десять секунд 2027 года, с собственной папкой профиля
chrono run "C:\Program Files\Mozilla Firefox\firefox.exe" --at 2027-12-31T23:59:50 --no-gecko-sandbox --args "-no-remote -profile C:\ff-test http://localhost:8080/"

В Firefox сдвигается весь браузер, а не только страницы, включая проверку сертификатов: в сессии, установленной на 2040 год, настоящий сайт по HTTPS показал предупреждение о безопасности. Работает это для страниц из файла, вашего тестового сервера или даты, которую сертификат сайта ещё покрывает.

Запущенный от имени администратора Firefox отказывается от прав и перезапускается вне сессии, если среди его аргументов нет --no-deelevate, и сессия сообщает об этом с самого начала.

Как узнать, что страницы получили дату

Отчёт говорит, до каких страниц и worker'ов сессия дотянулась, а какие остались на настоящих часах, - в Chrome по каждому контексту JavaScript, в Firefox по каждому процессу. Что говорит отчёт →

Чего это не делает

  • Серверная сторона. Дата, которую сайт получает от своего сервера, остаётся датой сервера.
  • Ваш повседневный браузер. Сессия запускает собственный браузер. Она не подключается к уже открытому и не трогает его вкладки и входы.
