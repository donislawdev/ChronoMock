การเปลี่ยนวันที่ใน Chrome หรือ Firefox เพื่อทดสอบ

คำตอบทั่วไปคือส่วนขยายที่แทนวันที่ในหน้าเว็บ หรือนาฬิกาของเฟรมเวิร์กทดสอบ Chrono Mock เริ่มตัวเบราว์เซอร์เองด้วยนาฬิกาของมันเอง ทุกแท็บและทุก worker ในวันที่ใดก็ได้ หยุดนิ่งหรือเร่ง โดยไม่แตะนาฬิกา Windows และโปรแกรมอื่นทั้งหมด

คำตอบทั่วไปครอบคลุมอะไร

วิธีใครเห็นวันที่ใหม่สิ่งที่ตกหล่น
ส่วนขยายเบราว์เซอร์วันที่ของ JavaScript ในหน้าที่มันได้รับอนุญาตให้เข้ามักทีละแท็บ และไม่มีอะไรบอกว่ามันพลาดอะไรไป
Chrome DevToolsเขตเวลา ตั้งผ่านตำแหน่งในแผง Sensorsตัววันที่เอง
นาฬิกาของเฟรมเวิร์กทดสอบหน้าที่การทดสอบที่คุณเขียนเปิดการทดสอบด้วยมือ และทุกหน้าที่การทดสอบไม่ได้ควบคุม
นาฬิกา Windowsทุกอย่างบนเครื่องไม่ตกหล่นอะไร และนั่นคือปัญหา ใบรับรอง การล็อกออนโดเมน และการซิงก์เวลาก็เลื่อนตามไปด้วย

การเปลี่ยนนาฬิกา Windows ทำอะไรพังบ้าง →

Chrome

Chrome เริ่มด้วยโปรไฟล์ใช้ครั้งเดียวที่สะอาดและพอร์ตดีบักในเครื่อง ทุกหน้าและทุก worker รับเวลา JavaScript จากเซสชัน ได้แก่ Date.now, new Date(), performance.now, setTimeout, setInterval และเขตเวลาของเซสชัน ตัวเบราว์เซอร์เองยังใช้วันที่จริง เว็บไซต์ HTTPS จึงยังโหลดได้ ตรวจแล้วกับเซสชันที่ตั้งเป็นปี 2040 

# Chrome ในสิบวินาทีสุดท้ายของปี 2027 เร็วขึ้นหกสิบเท่า
chrono run "C:\Program Files\Google\Chrome\Application\chrome.exe" --at 2027-12-31T23:59:50 --mode x60 --args "http://localhost:8080/"

โปรไฟล์นั้นไม่ใช่ของคุณ ไม่มีการล็อกอินที่บันทึกไว้ ไม่มีส่วนขยาย และจะถูกลบเมื่อเซสชันจบ เบราว์เซอร์อื่นที่สร้างบน Chromium ก็ทำงานแบบเดียวกัน โหมด Chromium ทำงานอย่างไร →

Firefox

Firefox รันหน้าเว็บในโปรเซสแซนด์บ็อกซ์ที่เซสชันเข้าไปไม่ได้ จึงต้องใช้ --no-gecko-sandbox เมื่อนั้นหน้าเว็บจะเริ่มนอกแซนด์บ็อกซ์ เข้าร่วมเซสชัน และตามนาฬิกา ความเร็ว การกระโดด และเขตเวลาของเซสชัน Firefox จะทำงานโดยไม่มีการป้องกันนั้นจนกว่าจะปิด จึงควรเปิดเฉพาะหน้าที่คุณไว้ใจ ให้โปรไฟล์ของมันเองด้วย -no-remote -profile และโฟลเดอร์ว่าง เพื่อไม่ให้มันส่งหน้าเว็บไปให้ Firefox ที่คุณเปิดอยู่แล้ว 

# Firefox ในสิบวินาทีสุดท้ายของปี 2027 พร้อมโฟลเดอร์โปรไฟล์ของตัวเอง
chrono run "C:\Program Files\Mozilla Firefox\firefox.exe" --at 2027-12-31T23:59:50 --no-gecko-sandbox --args "-no-remote -profile C:\ff-test http://localhost:8080/"

ใน Firefox ทั้งเบราว์เซอร์เลื่อนไป ไม่ใช่แค่หน้าเว็บ และรวมถึงการตรวจใบรับรองด้วย ในเซสชันที่ตั้งเป็นปี 2040 เว็บไซต์ HTTPS จริงแสดงคำเตือนด้านความปลอดภัย กรณีที่ใช้ได้คือหน้าจากไฟล์ เซิร์ฟเวอร์ทดสอบที่คุณรันเอง หรือวันที่ที่ใบรับรองของเว็บไซต์ยังครอบคลุมอยู่

เมื่อเริ่มแบบผู้ดูแลระบบ Firefox จะทิ้งสิทธิ์นั้นและเริ่มใหม่นอกเซสชัน เว้นแต่จะมี --no-deelevate ในอาร์กิวเมนต์ และเซสชันจะบอกเรื่องนี้ตั้งแต่ต้น

รู้ได้อย่างไรว่าหน้าเว็บได้รับวันที่แล้ว

รายงานบอกว่าเซสชันเข้าถึงหน้าและ worker ใดบ้าง และอันใดยังอยู่บนนาฬิกาจริง ใน Chrome แยกตามบริบท JavaScript ใน Firefox แยกตามโปรเซส รายงานบอกอะไร →

สิ่งที่มันไม่ทำ

  • ฝั่งเซิร์ฟเวอร์ วันที่ที่เว็บไซต์ได้จากเซิร์ฟเวอร์ของมันยังคงเป็นวันที่ของเซิร์ฟเวอร์
  • เบราว์เซอร์ที่คุณใช้ทุกวัน เซสชันเริ่มเบราว์เซอร์ของตัวเอง ไม่เกาะกับเบราว์เซอร์ที่คุณเปิดอยู่ และไม่แตะแท็บหรือการล็อกอินของมัน
