テストのために Chrome や Firefox の日付を変更する

よくある答えは、ページの日付を置き換える拡張機能か、テスト フレームワークの時計です。Chrono Mock はブラウザーそのものを専用の時計で起動します。すべてのタブとすべての worker が、任意の日付で、止めることも速めることもでき、Windows の時計とほかのプログラムには手を触れません。

Chrome

Chrome はまっさらな使い捨てプロファイルとローカルのデバッグ ポートで起動し、すべてのページと worker が JavaScript の時刻をセッションから受け取ります。Date.now, new Date(), performance.now, setTimeout, setInterval、そしてセッションのタイムゾーンです。ブラウザー自体は本物の日付のままなので、HTTPS のサイトは問題なく読み込めます。2040 年に設定したセッションで確認済みです。 

# Chrome を 2027 年の最後の 10 秒で、60 倍速で動かす
chrono run "C:\Program Files\Google\Chrome\Application\chrome.exe" --at 2027-12-31T23:59:50 --mode x60 --args "http://localhost:8080/"

このプロファイルはあなたのものではありません。保存されたログインも拡張機能もなく、セッション終了時に削除されます。Chromium ベースのほかのブラウザーも同じように動きます。 Chromium モードのしくみ →

Firefox

Firefox はセッションが入れないサンドボックス内のプロセスでページを動かすので、--no-gecko-sandbox が必要です。するとページはサンドボックスの外で起動し、セッションに加わって、その時計、速度、ジャンプ、タイムゾーンに従います。Firefox は閉じるまでその保護なしで動くので、信頼できるページだけを開いてください。-no-remote -profile と空のフォルダーで専用のプロファイルを与えれば、すでに開いている Firefox にページを渡してしまうこともありません。 

# Firefox を 2027 年の最後の 10 秒で、専用のプロファイル フォルダーで動かす
chrono run "C:\Program Files\Mozilla Firefox\firefox.exe" --at 2027-12-31T23:59:50 --no-gecko-sandbox --args "-no-remote -profile C:\ff-test http://localhost:8080/"

Firefox ではページだけでなくブラウザー全体が動き、証明書の検査も含まれます。2040 年に設定したセッションでは、本物の HTTPS サイトがセキュリティ警告を表示しました。うまくいくのは、ファイルから開くページ、自分で動かすテスト サーバー、またはサイトの証明書がまだ有効な日付です。

管理者として起動すると、Firefox は権限を捨ててセッションの外で起動し直します。引数に --no-deelevate があれば別で、セッションはこのことを最初から伝えます。

レポートは、セッションが届いたページと worker、本物の時計のままだったものを示します。Chrome では JavaScript のコンテキストごと、Firefox ではプロセスごとです。 レポートの内容 →

できないこと

  • サーバー側。 サイトが自分のサーバーから受け取る日付は、サーバーの日付のままです。
  • 普段使いのブラウザー。 セッションは専用のブラウザーを起動します。開いているブラウザーにはつながらず、そのタブやログインには触れません。
