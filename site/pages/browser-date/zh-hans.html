为测试更改 Chrome 或 Firefox 的日期

常见的答案是一个在页面里替换日期的扩展，或测试框架的时钟。Chrono Mock 直接用独立的时钟启动浏览器本身：每个标签页和每个 worker，任意日期，可冻结或加速，而 Windows 时钟和其他所有程序都不受影响。

方法谁看到新日期漏掉了什么
浏览器扩展它能进入的页面里的 JavaScript 日期往往一次只管一个标签页，而且不会告诉你漏掉了什么
Chrome DevTools时区，通过 Sensors 面板里的位置设置日期本身
测试框架的时钟你写的测试打开的页面手动测试，以及测试没有驱动的每个页面
Windows 时钟整台机器上的一切什么都不漏，这正是问题：证书、域登录和时间同步也一起移动

Chrome

Chrome 以干净的一次性配置文件和本地调试端口启动，每个页面和 worker 都从会话获取 JavaScript 时间：Date.now, new Date(), performance.now, setTimeout, setInterval，以及会话时区。浏览器本身保持真实日期，所以 HTTPS 网站照常加载 - 已在设为 2040 年的会话中验证。 

# Chrome 处于 2027 年最后十秒，以六十倍速运行
chrono run "C:\Program Files\Google\Chrome\Application\chrome.exe" --at 2027-12-31T23:59:50 --mode x60 --args "http://localhost:8080/"

这个配置文件不是你的：没有保存的登录、没有扩展，会话结束后即被删除。其他基于 Chromium 的浏览器同样适用。 Chromium 模式如何工作 →

Firefox

Firefox 在会话进不去的沙盒进程中运行页面，因此需要 --no-gecko-sandbox。这样页面会在沙盒外启动，加入会话，跟随它的时钟、速度、跳转和时区。在关闭之前，Firefox 都没有这层保护，所以只在里面打开你信任的页面。用 -no-remote -profile 加一个空文件夹给它一个独立配置文件，这样它不会把页面交给你已经打开的 Firefox。 

# Firefox 处于 2027 年最后十秒，使用独立的配置文件夹
chrono run "C:\Program Files\Mozilla Firefox\firefox.exe" --at 2027-12-31T23:59:50 --no-gecko-sandbox --args "-no-remote -profile C:\ff-test http://localhost:8080/"

在 Firefox 中，移动的是整个浏览器而不只是页面，证书检查也包括在内：在设为 2040 年的会话中，一个真实的 HTTPS 网站显示了安全警告。来自文件的页面、你自己运行的测试服务器，或网站证书仍然覆盖的日期，才是可行的情况。

以管理员身份启动时，Firefox 会放弃权限并在会话之外重新启动，除非它的参数里有 --no-deelevate，会话从一开始就会说明这一点。

如何知道页面拿到了日期

报告会说明会话到达了哪些页面和 worker，哪些仍用真实时钟：Chrome 按每个 JavaScript 上下文，Firefox 按每个进程。 报告说明了什么 →

它不做什么

  • 服务器端。 网站从自己服务器拿到的日期仍是服务器的日期。
  • 你日常用的浏览器。 会话启动的是它自己的浏览器。它不会附加到你已经打开的浏览器，也不碰其中的标签页和登录。
