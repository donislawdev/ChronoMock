JSON output

With --json, every chrono command writes its answer for a program to read rather than for a person: a script, a test or a step of a pipeline. This page names every field.

How it works

  • Standard output carries the JSON and nothing else. Messages for people go to standard error, and so does the console output of an application that chrono run starts.
  • The exit code is the same as without --json, so a script can act on it before it reads a single field. Exit codes lists them.
  • calc, presets, calendars and run --dry-run write one JSON document on one line. Its first field, schema, names which one it is. chrono run writes a line for each thing that happens while the session runs.
  • Fields and kinds of line are added from version to version. A program that reads this output should pass over what it does not know. Every change to a field is named in the changelog.
  • A field marked {{next_release}} is not in the latest release yet and comes with the next one.

Dates, times and zones

A date and time is written as a clock on the wall shows it, without its zone, such as 2038-01-19T03:14:07. The zone is in the field beside it, zone_bias_min: the minutes to add to that time to get UTC, the way Windows counts them. UTC+02:00 is -120, UTC-05:00 is 300 and UTC is 0. The sign is the opposite of the one in +02:00, so check it before you convert.

chrono calc --json

moment.presetWith --preset: its id, its name and explains, the sentence on what it tests.

A pasted date, --analyze, comes as analysis instead, with one reading or two:

FieldWhat it holds
analysis.inputThe text, as it came.
analysis.ambiguoustrue when it reads two ways, as 04/08/2008 does.
analysis.zone_bias_minThe zone the readings are in. It matters for a number such as Unix time, which is an instant: its date and time are given in this zone. A date written out does not move with it.
analysis.readings[].readingWhich reading: iso, us_month_day, pl_day_month, epoch_seconds or epoch_millis.
analysis.readings[].isoThe reading as a date and time.
analysis.readings[].instanttrue for a number of seconds or milliseconds since 1970.
analysis.readings[].timeThe time of day to show with it, HH:MM:SS, or null when there is none to show, as for a date written without a time.
analysis.readings[].significanceWhat it lands on, in the same words as moment.significance.
analysis.readings[].metadataThe same fields as moment.metadata.

The words of significance:

  • start_of_month, start_of_quarter, start_of_year: the first day of the period, at any time of that day. Only the largest one, so 1 January is start_of_year alone.
  • end_of_month, end_of_quarter, end_of_year: the last day, the same way.
  • leap_day: 29 February. last_day_of_february_common_year: 28 February in a year without a 29th.
  • unix_epoch: exactly 1970-01-01 00:00:00 UTC. year_2038_boundary: 2038-01-19 03:14:07 UTC or later, where a count of seconds in 32 bits runs out.
  • With --calendar: weekend, public_holiday (a holiday on its own date) and observed_holiday (a weekday off because a holiday fell on the weekend).
  • before_calendar: a year before the calendar's first one, so the date was not judged.
  • calendar_outdated: the calendar was last checked against the law more than a year ago, and the answer depends on a day after that check, so a change in the law since then may be missing.

When calc cannot do what you asked, standard output stays empty and the reason is on standard error, with one of the codes Exit codes lists.

chrono presets --json

Schema chronomock.presets/1. Every preset the program reads, the way --preset reads it, and every file it refuses, with the reason. A refused file is a part of the answer, so the command still ends with 0. It ends with 1 only for a wrong option or a folder it cannot read. What each preset is for is on Scenarios.

chrono run --dry-run --json

Schema chronomock.plan/1. What a session would be, worked out without starting anything: no application starts and no file is written. It ends with 0 when the session could start, and with the code the session would end with when it could not.

{
  "schema": "chronomock.plan/1",
  "started": false,
  "target": { "path": "C:\\apps\\test.exe", "resolved": "C:\\apps\\test.exe", "state": "found",
              "program": null, "args": [], "cwd": null },
  "mechanism": "native",
  "core_bitness": "x64",
  "time": { "moment": "2038-01-19T03:14:07", "zone_bias_min": 0, "zone_from_flag": true,
            "mode": "flow", "multiplier": null, "scale_duration": false, "scale_qpc": false },
  "origin": { "kind": "at", "at": "2038-01-19T03:14:07", "preset": null, "parameters": [] },
  "session": { "ticks": 0, "timeout_secs": null, "set_after": null, "jump_after": null,
               "force": false, "embedded": true, "elevated_embedded": false,

chrono run --json

Instead of the report, a session writes one JSON line for each thing that happens, as it happens. Every line has type, which says what the line is, and v, the version of the lines. A short session looks like this, with the list of clocks cut short: 

chrono run C:\apps\test.exe --at 2038-01-19T03:14:07 --zone +00:00 --ticks 2 --json
{"type":"ready","v":1,"protocol":1,"core_version":"0.6.0-rc.1","bitness":"x64","capabilities":[]}
{"type":"coverage","v":1,"pid":71984,"kind":"process","covered":[{"channel":"GetSystemTimeAsFileTime","calls":1},...],"observed":[...],"uncovered":[],"unobserved":[],"installed_late":[],"warning_keys":[]}
{"type":"verdict","v":1,"id":1,"verdict":"works","refuse_start":false,"reason_key":"coverage.time_channels_covered"}
{"type":"state","v":1,"fake":{"wall":"2038-01-19T03:14:08","zone_bias_min":0},"real":{"wall":"2026-11-24T13:51:09","zone_bias_min":0},"multiplier":1,"elapsed_fake_ms":1563,"elapsed_real_ms":1563}
{"type":"state","v":1,"fake":{"wall":"2038-01-19T03:14:09","zone_bias_min":0},"real":{"wall":"2026-11-24T13:51:10","zone_bias_min":0},"multiplier":1,"elapsed_fake_ms":2565,"elapsed_real_ms":2565}
{"type":"coverage","v":1,"pid":71984,"kind":"process","covered":[...],...}
{"type":"session_verdict","v":1,"verdict":"works","reason_key":"session.family_covered","process_count":1,"warning_keys":["session.left_running"],...}
{"type":"ended","v":1,"clean":true,"residue_keys":[],"target_exit_code":null,"elapsed_real_ms":2569,"elapsed_fake_ms":2569,"fake_end_wall":"2038-01-19T03:14:09"}
LineWhenFields
readyFirst: the session is ready to start.protocol, core_version, bitness, capabilities
coverageFor each process the session reaches, or each web page in the Chromium mode, when it is reached and again at the end: the clocks it read and how many times.pid, kind, covered, observed, uncovered, unobserved, installed_late, warning_keys
verdictRight after the start: whether the application reads the session's clock. With refuse_start the session ends the application, unless --force was given.id, verdict, refuse_start, reason_key, left_running, family_search_incomplete
ackA change of speed or a jump from --set-after or --jump-after was made.id
stateAbout once a second: the session's clock and the real one side by side.fake, real, multiplier, elapsed_fake_ms, elapsed_real_ms
host_sleptThe computer slept during the session. The session's clock stood still while it slept.slept_ms, total_slept_ms
vanishedThe application closed right after the start, most likely handing its work to a copy of it that was already running. The command ends with 12.pid, reason_key, lived_ms
errorSomething failed, named by key. Before the start it means the session never began.id, code, key, origin
session_verdictOnce, at the end: the verdict for the application and every process it started. The exit code says the same.verdict, reason_key, process_count, warning_keys, uncovered_children, uncovered_children_total, context_count, engines, followed, copies_outside, host_slept_ms, browser
endedLast: the session is over.clean, residue_keys, target_exit_code, elapsed_real_ms, elapsed_fake_ms, fake_end_wall

The fields a pipeline usually needs:

  • verdict of session_verdict: works, partial, fails or undetermined, the four verdicts the exit codes 0, 10, 11 and 4 carry.
  • reason_key, warning_keys, residue_keys and key name what happened in a few words that do not change between versions, such as session.left_running. The report puts the key of a warning or an error in brackets after the sentence that explains it.
  • process_count: how many processes the verdict covers, the application and everything it started.
  • target_exit_code of ended: the code the application ended with when it closed itself. Null when the session ended first, which --ticks and --timeout do. It is not the exit code of chrono.
  • fake and real of state: each a wall clock and its zone_bias_min.

A session cut short by --timeout ends without the last two lines, and the command ends with 6.
