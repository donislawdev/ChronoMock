Your first session

Run an application as if it were 19 January 2038, see that it read that date, and read what Chrono Mock says about it. The clock of your computer stays as it is.

Get Chrono Mock

Download it from the download page. The zip runs from any folder with nothing to install, and the installer adds it to the Start menu. Start ChronoMock.exe: it opens on Run an app.

1. Pick the application

Press Choose… and pick the .exe of the application you are testing. The list beside the button keeps the applications you have run before.

2. Pick the date

Starts at is the date and time the application starts at. It opens on the last second a 32-bit Unix clock can count, 03:14:07 UTC on 19 January 2038, which is a common first test. Type another date, pick one from the calendar, or use:

  • Today or Now, for today at midnight or this moment,
  • From now and Fill the date, for a date counted from now, such as 90 days ahead,
  • Scenarios, for a ready-made date such as the last day of the month (see Scenarios).

Time zone is the zone the application finds itself in for the session, and the date and time above are read in it. It is a fixed offset from UTC, with no change for daylight saving. The footer says in words what the application will see.

3. Start

Start starts the application with its clock set to that moment, while the rest of the computer keeps the real time. Chrono Mock shows both clocks side by side.

  • Speed runs the fake clock faster, or freezes it.
  • Jump moves it by an hour or a day, and Jump to to any date and time. A jump back moves the date and time back, but the clock an application measures elapsed time with never runs backwards.
  • Stop session puts the application back on the real clock. It does not close the application.

The verdict next to Running says whether the application really reads the fake clock. When the check right after the start finds that it does not, the session ends the application, rather than leave it running on dates it never got.

4. Read the result

When the application closes, or you stop the session, the result stays on screen.

  • Works: every process that read the time saw the fake clock.
  • Partial: the application read some of its time from the real clock, so the test may be unreliable.
  • Fails: it went on reading the real clock where it matters.
  • Undetermined: what it read could not be determined, which never counts as working.

What the application saw gives the moment it started at, the speed, where the fake clock got to, and how much time passed on each clock. What the application read lists each way of reading the time it used, and which clock answered.

Copy summary copies a report to paste into a ticket. New session goes back to the setup with everything you entered, and Previous sessions keeps the sessions before, to set one up again. The time source audit explains what is read and why.
